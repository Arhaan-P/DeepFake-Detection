## 2. Architecture: what the code actually does

### 2.1 The verification head does not use the CNN/BiLSTM/Transformer stack

This is the most consequential finding in the whole review and it is not a
documentation problem — it is a modelling one.

In `models/full_pipeline.py:239-247`, verification-mode logits are computed as:

```python
diff     = video_features - claimed_features     # raw 78-dim, NOT encoded
abs_diff = torch.abs(diff)
product  = video_features * claimed_features
combined = torch.cat([diff, abs_diff, product], dim=2)
x = self.diff_conv(combined.permute(0, 2, 1)).squeeze(-1)
logits = self.diff_classifier(x)
```

`encode_gait()` runs earlier in `forward()` and produces `video_embedding`, but
that tensor **never reaches the logits**. `scripts/training/train.py:162-169`
backpropagates cross-entropy on those logits alone, and no triplet or
contrastive loss is enabled. So the GaitEncoder, DualPathTemporalModel and
IdentityVerifier receive **no gradient** and affect **no prediction**.

Measured parameter split (by instantiating the model, not by reading docs):

| Module | Params | On decision path? |
|---|---|---|
| `diff_conv` | 131,936 | **yes** |
| `diff_classifier` | 1,122 | **yes** |
| `gait_encoder` | 129,600 | no |
| `temporal_model` | 546,304 | no |
| `identity_verifier` | 31,266 | no |
| `classifier` | 8,386 | no |
| **Total** | **848,614** | **133,058 live (15.7%)** |

**Resolution (your option 1):** the paper's title is now "Detecting Face-Swap
Deepfakes by Verifying Skeletal Gait Dynamics" — no "hybrid architecture"
claim. Section III-E describes the difference-based temporal CNN as the trained
decision function. Section III-F describes the encoder/temporal stack honestly
as an auxiliary representation branch and states that no result in the paper is
evidence for or against it. Fig. 4's Gemini prompt draws the two lanes
separately and explicitly forbids an arrow between them.

**This also resolves your KNOWN ISSUE.** The README's Siamese-primary diagram is
wrong, and so is the "difference-based CNN plus hybrid classifier" reading —
the difference CNN is the *entire* classifier. `encoder_output_dim=128` from
`outputs/model_config.json` is used throughout, not the code defaults of 256.

### 2.2 The ablation study does not measure what it claims

All four variants in `scripts/evaluation/ablation_study.py` — `CNNOnlyModel`,
`LSTMOnlyModel`, `TransformerOnlyModel` and the full model — compute their
logits through an **identical** `diff_conv` → `diff_classifier` head on the same
raw comparison tensor. The named branch produces only an unused
`video_embedding`. I verified by instantiation: **every variant carries exactly
133,058 parameters on the decision path.**

The four "variants" are therefore one classifier trained four times. The
88.93 → 90.51% spread (1.58 points) is run-to-run variance from different random
initialisation of the surrounding modules, not component contribution.

**Resolution:** Table IX and Fig. 9 report the measured numbers, plus a
decision-path parameter column that makes the problem visible; Section V-D
states plainly that no component-contribution conclusion follows, and reuses the
spread as a useful noise-floor estimate (~2 accuracy points). Section VII-C
lists the corrected experiment — route each branch's embedding into the
classifier and retrain — as required future work.

**If you want the real ablation**, that is the change to make, and it is small:
concatenate `video_embedding` (or the branch's sequence output) into the
classifier input. I did not make it, per your option 1.

### 2.3 Attribution is gradient×input, not Grad-CAM

`JointImportanceAnalyzer` in `utils/gradcam.py:199-218` computes
`|x ⊙ ∂ℓ/∂x|` on the input, which is gradient×input attribution, not Grad-CAM.
Good news: because the gradient path runs through `diff_conv`, this attributes
the function that *actually* makes the decision, so the joint-importance results
are sound. The paper names the method correctly and cites Shrikumar et al. and
Sundararajan et al. alongside Grad-CAM (which is used, correctly, for the
temporal heatmap on the last conv layer).
